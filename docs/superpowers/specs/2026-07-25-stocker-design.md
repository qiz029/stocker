# Stocker — 时间旅行股票竞技游戏 设计文档

日期：2026-07-25
状态：待用户审阅

## 1. 概述

一个 Web 端多人股票竞技游戏。玩家开一个私密房间邀请朋友，一起"回到"某个历史时期（首个剧本：2000 年互联网泡沫），在真实历史行情之上竞技交易，看谁在泡沫与崩盘中活得最好。

核心体验：**多人竞技比拼**。异步长局（一局 1–4 周现实时间），玩家每天上线看行情、读新闻、调仓。

核心卖点：

- **重新经历真实历史**：大势就是真实历史（泡沫照样吹起、崩盘照样发生）。
- **盲盒模式**：隐藏真实日期与股名，无法查盘作弊；局终揭晓"啊原来是它"。
- **平行世界**：每局用房间种子生成不同的新闻时间线与价格扰动，同一段历史每局路径不同。

## 2. 玩法规则

### 2.1 一局的生命周期

1. 创建房间：选剧本、局长（现实 1 周 / 2 周 / 4 周，默认 2 周）。速率 = 局长 ÷ 剧本交易日数（2 周局约每 27 分钟推进一个历史交易日）。
2. 生成世界：系统用房间种子生成本局的新闻时间线与扰动价格（见 §4），界面显示"正在生成你们的平行世界…"。
3. 邀请链接拉朋友加入；房主点开始，时间轴启动。
4. 每天上线：看行情（当前历史日收盘数据）、读新闻、下单调仓。
5. 到达剧本终点自动结束，进入揭晓/复盘。

中途加入：允许，从当前时点以同等初始资金起步，排行榜标注"晚入场"。

### 2.2 交易

- 初始资金每人虚拟 $100,000，MVP 仅现货做多，不允许负现金。
- 玩家看到的行情永远截至"当前历史日"收盘；订单在**下一个历史交易日的开盘价**成交，杜绝看价成交。
- 成交价未知，因此**买入按金额下单**（成交后按开盘价折算股数），**卖出按股数下单**。下单即冻结现金/股数，成交日到来前可撤单。
- 排行榜按总资产（现金 + 持仓按当前历史日收盘估值）实时计算。房间内互相可见总资产与收益率，**不可见具体持仓**（局终揭晓）。

### 2.3 大额交易通报

- 单笔成交 ≥ 该玩家总资产 20%（阈值可调）时，房间动态流**匿名即时通报**：「有玩家大额买入 Coyote Networks」。
- 有信号价值但不暴露身份，玩家可以互相猜。

### 2.4 盲盒模式

- 标的化名：如「Coyote Networks — 网络设备巨头」，保留行业与公司描述供选股判断。
- 价格全部归一化为起始 100；成交量只显示相对变化；日期显示为「第 1 年第 37 个交易日」。
- 叠加每局不同的扰动后，即使认出走势也对不上精确点位。
- 局终揭晓：真实股名、真实日期区间、真实历史事件标注、每人资产曲线与关键操作复盘。

## 3. 标的范围（2000 剧本）

约 30 只精选标的 + 指数：网络设备（思科、朗讯）、门户（雅虎、AOL）、电商（亚马逊、eBay、Pets.com）、芯片（英特尔、AMD）、软件（微软、甲骨文）、电信（世通、环球电讯）等明星股与烈士股，加纳指/标普指数。每只标的配化名档案与因子暴露向量。

第二阶段剧本：2008 金融危机、比特币时代。

## 4. 新闻与多因子扰动系统

（数学骨架继承自旧项目 simstocks 的"因子内积 + 冲击叠加 + 指数衰减"，改乘法更新、种子确定性、双时间尺度；详见 §11。）

### 4.1 因子结构 — 50 维分层

- 系统性因子约 20 个：市场、风险情绪（VIX 类）各 1；剧本行业因子 12–14 个（2000 剧本细切科技：网络设备、门户、电商、芯片、软件、电信…）；宏观/风格因子 6–8 个（利率、原油、黄金、美元、大小盘、成长价值）。
- 特质因子：每只标的一个专属通道（30 只标的 = 30 维），个股新闻主要打这里。
- 合计约 50 维。因子集是剧本数据的一部分，不写死，按剧本定制（2008 剧本换成投行/地产/保险等）。
- 标的暴露向量 β 由数据管线用真实历史数据对真实 ETF/指数回归估算，再人工微调。

### 4.2 扰动引擎

对数空间状态 `X(d) = X_fast(d) + X_slow(d)`，逐因子维护：

```
X_fast(d) = λ_f · X_fast(d-1) + shock_fast(d)     λ_f = 0.7  （半衰期约 2 个交易日）
X_slow(d) = λ_s · X_slow(d-1) + shock_slow(d)     λ_s = 0.99 （半衰期约 70 个交易日）
显示价(i,d) = 基线价(i,d) × exp(clamp(Σ_f β_{i,f}·X_f(d) + ε_i(d), ±0.30))
```

- 每条冲击新闻的对数冲击按比例（约 65/35）分配到快/慢通道；冲击幅度 ~ Gamma(2, ·)，均值 2–2.5%，方向略偏空（45% 正 / 55% 负）。
- 每日微噪声 ε ~ N(0, 0.4%)。
- 参数经蒙特卡洛校准（2000 种子 × 750 天）：额外日波动约 1.6%（约为 dot-com 个股自身日波动 3–6% 的三到五成）；偏离基线中位约 3%、p95 约 9%、最大约 26%；clamp 零触发（纯保险丝）。校准脚本随数据管线入库，移植为 Go 性质测试。
- 定版校准以"扰动波动 ≈ 个股自身波动的 30–50%"为目标，真实基线数据进来后逐股校准。

### 4.3 新闻三轨制（解决"过度依赖自动触发"）

所有新闻在开局预生成，运行期没有任何触发逻辑。三个来源混合，玩家无法分辨：

1. **历史解释性新闻**：数据管线扫描基线数据的大波动日与趋势拐点（单日 |涨跌| > 6%、连跌数周等），为其生成报道。**不注入冲击**（影响已在历史价格里），作用是让世界对行情有反应——崩盘日必有恐慌头条。
2. **冲击新闻**：随机时间线上的事件，通过因子模型注入真实扰动。
3. **纯噪音新闻**：零影响的花边与口水。

### 4.4 真实/报道解耦（解决"新闻太直白"）

- 每条冲击新闻有真实冲击向量 `v_true`（注入模型）与报道向量 `v_report = ρ·v_true + 噪声`（喂给 LLM）。
- ρ 为该虚拟"媒体"的信誉度：通讯社高、小报低。玩家可以学习哪个媒体可信，构成元玩法。
- 幅度错配按比例掺入：大标题小冲击、短讯大冲击。
- 新闻簇：大事件拆成"传闻 → 证实/辟谣 → 后续分析"跨天多条，慢通道漂移与后续报道对齐，叙事展开式。
- LLM prompt 要求含糊、多方观点、对冲措辞；禁止"应声大涨"式看图说话（旧版"必须与冲击方向高度一致"的要求删除）。

### 4.5 新闻发布与成交的衔接

新闻在"当前历史日"收盘后发布，影响从下一开盘生效——玩家读新闻 → 判断 → 下单 → 下一开盘成交，反应快的人有真实优势。

### 4.6 大势保真的四层机制

1. **结构保证**：扰动是均值回归的（OU 式），期望回到 0，趋势 100% 来自基线；扰动幅度（最大约 25%）与历史行情本身（纳指 -78%、思科 -90%）差数量级，不可能反转大势，只能让崩盘"早几天晚几天、深一点浅一点"。
2. **clamp 保险丝**：|X 合成| ≤ 0.30 硬上限。
3. **历史关键期冲击抑制**：剧本标注关键窗口（如 2000 年 3–4 月见顶期），窗口内降低逆历史方向大冲击的采样权重、提高顺方向权重——火上浇油可以，泼冷水不行。
4. **剧本生成自动校验**：任意种子下，扰动后日收益与基线相关性 ≥ 0.85；每只标的整局累计涨跌方向与历史一致；历史峰/谷日在扰动后 ±10 个交易日内仍为局部极值。不达标的参数组合拒绝。

## 5. 架构

### 5.1 组件

- **前端**：React SPA（Vite + TypeScript）。无 WebSocket，房间页 30–60 秒轮询动态。
- **后端**：单个 Go 服务（net/http + chi），bcrypt 用户名密码 + session cookie，自足无第三方依赖。
- **存储**：Postgres 单库。
- **离线数据管线**：独立 Go 命令行程序（开发期运行），见 §7。
- **唯一外部依赖**：开局时一次性调用 LLM API 批量生成新闻文案；失败自动降级到内置模板文案，游戏照常开。运行期零外部依赖，无任何 cron/定时任务/云服务。

### 5.2 确定性时间轴（无调度架构）

- 房间记录 `started_at` 与每历史交易日的现实秒数。任何时刻：`当前历史日 = min(floor((now − started_at) / day_duration), 剧本天数 − 1)`，超过即局终。
- 纯函数，无后台推进任务，服务器重启零恢复成本。

### 5.3 开局生成（房间创建时一次完成）

种子 → 冲击新闻时间线（含关键期抑制）→ 逐日逐因子扰动状态 → 合成全部显示价格写入 `room_prices` → 组装三轨新闻 → LLM 批量生成文案（降级：模板）→ 写入 `room_news`。之后运行期只是按"当前历史日"读表。

### 5.4 惰性结算

订单落库时记 `exec_day = 下单时刻的当前历史日 + 1`。无撮合任务；任何读取组合/排行的请求先在事务里把 `exec_day ≤ 当前历史日` 的未结算订单按开盘价结算（幂等），再返回。谁先来谁触发，结果一致。

## 6. 数据模型

- `users`、`sessions`
- `scenarios`（剧本元数据、因子定义、关键窗口标注）
- `instruments`（化名档案、真实身份、β 向量）
- `scenario_prices`（归一化基线日线 OHLC）
- `rooms`（剧本、种子、`started_at`、day_duration、状态）、`room_players`
- `room_prices`（该房间扰动后最终价格序列）
- `room_news`（该房间新闻时间线：发布日、媒体、文案、轨别与冲击参数——轨别不下发前端）
- `orders`（含 exec_day、冻结额、状态）、`trades`、`positions`
- 房间动态流（大额通报等）可从 trades 派生或单独 `room_events` 表

## 7. 数据管线（离线工具）

1. 从公开数据源拉取真实日线（股票、指数、ETF）。
2. 清洗：拆股/分红复权、缺数据处理、退市股处理。
3. 归一化起始价为 100。
4. β 估算：对真实 ETF/指数回归，人工微调。
5. 化名档案编写（名称、行业描述）。
6. 扫描大波动日/拐点生成历史解释性新闻的素材标注。
7. 扰动参数逐股校准（目标：扰动波动 ≈ 自身波动 30–50%）+ §4.6 的自动校验。
8. 打包剧本导入 Postgres。

## 8. API 与前端页面

REST 概要：注册/登录；创建/加入/开始房间；房间状态（行情列表、当前历史日、排行、动态流增量）；个股详情（K 线、化名档案、新闻）；下单/撤单/持仓；局终揭晓数据。

页面：登录注册 → 大厅（我的房间 + 创建房间）→ 房间主页（行情、资产、排行、动态流）→ 个股页（K 线 + 档案 + 下单）→ 揭晓/复盘页。

## 9. 测试策略

- 时间映射、惰性结算幂等性：单测。
- 同种子全链路可复现：golden test。
- 扰动有界性与大势保真（§4.6 条款）：性质测试，任意种子成立。
- 数据管线清洗校验：拆股缺口、复权正确性。
- 蒙特卡洛校准脚本移植为 Go 测试，参数改动即验证。

## 10. MVP 范围与分期

**MVP（第一期）**：注册登录、私密房间（邀请链接）、2000 剧本、确定性时间轴、现货买卖（买按金额/卖按股数、下一开盘成交、惰性结算）、盲盒化名+归一化、50 维因子扰动 + 三轨新闻 + LLM 开局文案（含模板降级）、匿名大额通报、动态流、排行榜、揭晓复盘页、数据管线工具。

**第二期**：做空/杠杆 + 爆仓（惰性重算历史路径实现，不破坏无调度架构）、限价单/止损单、2008 与比特币剧本、多视角记者报道（不同媒体立场/语言）、全服赛季榜、邮件通知。

## 11. 与旧项目 simstocks 的关系

继承（位于 `~/Workspace/golang/simstocks`）：

- 因子内积 + 冲击叠加 + 指数衰减的数学骨架（`momentum_ext.go`）。
- ETF 灰盒因子选取思路（因子有真实金融语义）。
- LLM 逆向生成新闻/公司档案的 prompt 积累（`internal/dal/agent/prompt.go`），多视角记者报道留作二期。
- 双轨制事件设计思想（历史轨在新设计中由真实价格基线承担）。

改动：

- 加法价格更新（`momentum_ext.go:30`，与其设计文档不符的实现 bug）→ 乘法 `exp(Σβ·X)`。
- 实时 tick 守护进程（`self_driver.go`）→ 开局一次性确定性预生成，运行期无触发。
- 未播种 `math/rand` → 一切随机性从房间种子派生，可复现。
- tick 循环内实时调 LLM → 开局批量生成 + 模板降级。
- 单一衰减率 → 双时间尺度（短期脉冲 + 中期漂移）。
- 随机生成股票向量 → 真实数据回归估算 β。
